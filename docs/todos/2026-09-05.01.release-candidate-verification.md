## Isolated native QA

Build explicitly with the QA override (it is not used by normal builds or releases):

```sh
pnpm tauri build --bundles app --config src-tauri/tauri.qa.conf.json
```

The override uses `dev.ashrimp.dlsite-manager.qa`, a distinct window title, and no updater
endpoints/artifacts. Tauri derives app data/log directories from the identifier, so the
regular app's database and credential vault are not opened. On macOS the QA database lives
under `~/Library/Application Support/dev.ashrimp.dlsite-manager.qa/`. This is a local QA build,
not a signed-updater artifact or a claim that public-distribution signing has been verified.

The identifier does **not** sandbox user-selected content folders. Before any sync/download,
select separate empty QA library and staging directories in Settings. Never select the
production library or its staging directory. Enter credentials/OTP only in the QA app;
do not paste them into chat or attach vaults, cookies, or raw authentication responses.
Do not use Check for Updates in this build: updates are intentionally disabled.

For an existing-data upgrade rehearsal, close both apps, make a consistent database backup
(SQLite backup or a copy after all connections are closed), and copy only test content.
Keep the original backup unchanged. Rebase copied settings **and download row paths** to
the copied content before opening the database in QA. Do not copy the production credential
vault. No real user database copy has been opened or modified by this task yet.

## Manual acceptance checks

- [ ] Add a 2FA account and sync; the prompt opens and a correct fresh OTP completes sync.
- [ ] Force a fresh login in the QA profile, submit one incorrect OTP, then a fresh correct
      OTP; distinguish code rejection from transport/reCAPTCHA failure without repeated guessing.
- [ ] Cancel a fresh-login prompt during sync, single download, and bulk download; the owning
      job is cancelled, later bulk works are not started, and earlier successes remain usable.
- [ ] Restart QA and repeat a job; a still-valid remembered session avoids another OTP prompt.
- [ ] Verify a non-2FA account if one is available; otherwise leave this check explicitly pending.
- [ ] With small disposable/copied works, verify replacement success, cancellation/failure,
      and restart recovery; previous content survives failed replacement and deletion removes
      the intended recovered content/staging without touching unrelated work.
- [ ] Check list/detail/filter changes, tag updates, open-folder actions, and the prompt at
      desktop and narrow widths; no stale detail or prompt may replace the current selection.
- [ ] Rehearse upgrade against an isolated, rebased copy of an existing user database/content.

Record pass/fail, OS, tested commit/build, and sanitized failure codes only. A reCAPTCHA
failure blocks live-2FA readiness and needs a separately scoped authentication design;
do not bypass the challenge or publish a claim that 2FA works on the basis of unit tests.

## Release gates

(tentatively `3.3.0-rc.1`), prepare `release`, and create a matching `v*` tag. RC tags publish
prereleases automatically; stable tags create drafts. Validate macOS/Windows/Linux artifacts,
signatures, installation, and updater behavior before approving stable publication. The QA
override must not be used for release or updater tests. Until then, do not tag or publish.

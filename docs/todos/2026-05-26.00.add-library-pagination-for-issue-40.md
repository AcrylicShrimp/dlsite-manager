## Context
GitHub issue #40 reports that the Library page only displays the first 100 products and has no pagination. The storage and Tauri command boundary already support limit/offset queries, and the frontend receives totalCount, but src/routes/+page.svelte currently always sends limit: 100 and offset: 0.

## Why It Is Needed
Users with more than 100 Library products cannot manually browse beyond the first page unless they already know a useful search/filter. Issue #40 specifically requests showing 100 at a time with page navigation, with one long list only as a fallback.

## Completion Criteria
- [ ] Library product requests use page-aware offset while keeping a 100 item page size.
- [ ] Search, filter, and sort changes reset pagination to the first page.
- [ ] Reload preserves the current page when still valid, and clamps/refetches if the result count shrinks below the current page.
- [ ] The Library header shows the visible product range and total count.
- [ ] Empty-result, loading, and normal range labels avoid impossible ranges such as `1-0 of 0`.
- [ ] Previous/Next page controls are available and disabled at list boundaries/loading states.
- [ ] Bulk download preview/download remains scoped to all matching products, not just the visible page.
- [ ] Validation passes: pnpm check, pnpm build, and git diff --check.
- [ ] docs/work-log.md records the implementation and validation outcome.

## Detailed Plan
1. Add small frontend pagination constants/state near existing Library product state.
2. Update productListRequest to derive offset from the current page index.
3. Add a loadProducts option for page-reset behavior and invalid-page clamping after totalCount is known.
4. Route search/filter/sort/reset actions through the first-page reset path; route plain Reload through current-page loading with invalid-page clamping.
5. Render Library range text and Previous/Next controls in the existing list header.
6. Add focused CSS for pagination controls, including mobile wrapping.
7. Validate with frontend checks and record the result in the work log.

# Investigate AppImage folder opening (#47)

## Status

Investigation complete; implementation and Linux runtime verification pending.
The request was to identify the cause and a solution, including verification without
a local Linux machine. No runtime code, dependencies, release workflow, or published
artifact was changed during this investigation.

## Evidence

- [Issue #47](https://github.com/AcrylicShrimp/dlsite-manager/issues/47) reports folder
  opening failure in a contributor-built v3.2.2 AppImage. It has no textual stderr,
  distribution/desktop details, or follow-up comments as of 2026-09-06. The attached
  video was not inspected; the exact reporter-side failure is not reproduced.
- `src-tauri/src/lib.rs` opens downloaded paths and the audit-log folder using
  `app.opener().open_path`. Existing downloaded-path canonicalization and configured
  root checks happen before launching and must remain intact.
- Locked `tauri-plugin-opener` 2.5.4 calls `open` 5.3.4's detached launcher. That
  launcher discards stdout/stderr and returns after spawning, without checking the
  desktop helper's eventual exit status. An audit success does not prove a folder opened.
- [Tauri #15804](https://github.com/tauri-apps/tauri/pull/15804) removes bundled
  xdg-open/xdg-mime and the CLI's automatic bundling of xdg-open when the opener
  dependency is present. It merged into dev on 2026-08-03; the change targets 2.12.
  Our npm CLI is locked to 2.11.1, and npm's latest was 2.11.4 when checked.
  Updating to the currently published CLI alone does not supply that fix.
- [Tauri #10078](https://github.com/tauri-apps/tauri/issues/10078) documents both
  bundled xdg-open incompatibility and host KDE helpers failing against bundled
  libraries. #15804 also explicitly notes remaining command environment cleanup.
  These are strong candidate causes, not proof of the reporter's exact failure.

## Proposed fix

- Add a small Linux desktop-launch module in the Tauri adapter; this is OS integration,
  not library business logic. Route both folder commands through it.
- For AppImage runs, resolve the host's xdg-open outside APPDIR. Avoid relying on the
  contaminated PATH alone, and avoid a sole hardcoded `/usr/bin/xdg-open` dependency
  (hosts such as NixOS can use other paths).
- Clean only the child environment: remove AppDir entries from PATH and
  LD_LIBRARY_PATH, and inspect the actual AppRun script for other injected variables
  such as GTK/GIO paths and XDG_DATA_DIRS. Preserve legitimate host paths and the
  desktop session variables (DISPLAY, WAYLAND_DISPLAY, DBUS_SESSION_BUS_ADDRESS,
  XDG_RUNTIME_DIR). Do not globally clear the running app's environment.
- Use a working directory outside the AppImage mount and pass the absolute path as
  one process argument, without a shell. Preserve Unicode and spaces.
- Observe helper failures asynchronously and capture bounded diagnostics for existing
  audit/error reporting. Do not block a Tauri command thread while a desktop helper
  remains running; distinguish launch acceptance from proof that a window opened.
- As an alternative/companion packaging fix, omit bundled xdg utilities in the existing
  Linux repack step. Revisit its early return when no libwayland-client is found, and
  preserve final-artifact re-signing. This alone does not fix inherited library paths.
- External URL opening also uses Opener (`src/lib/api/native.ts`); test it for the
  same AppImage problem before deciding whether to extend the change's scope.

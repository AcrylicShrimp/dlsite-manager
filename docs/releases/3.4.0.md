# dlsite-manager 3.4.0

This release adds diagnostic exports for troubleshooting and fixes update checks
that fail when GitHub rejects the updater's default request header.

## Added

- Activity now offers diagnostic ZIP export, a copyable support summary, and
  records grouped by app run and operation.
- Diagnostic records include selected, sanitized startup environment information,
  structured failure causes, and logging health. Bulk-download and post-sync scan
  failures retain their individual context. Nothing is uploaded automatically.

## Fixed

- Send `Accept: */*` when checking GitHub Releases for updates. GitHub currently
  returns HTTP 500 for otherwise identical requests using `Accept: application/json`,
  which appeared as “Could not fetch a valid release JSON from the remote”.

## Upgrading

If Check for Updates fails in your installed version, download and install 3.4.0
from this release manually. The request fix takes effect after installing 3.4.0;
publishing this release cannot repair the request made by older clients.

## Known limitations

- Linux folder opening still uses the original Tauri opener. This release improves
  diagnostics and does not claim to resolve [#47](https://github.com/AcrylicShrimp/dlsite-manager/issues/47).
  A successful open request does not establish that a file-manager window appeared.
- OrbStack Ubuntu/IceWM testing does not cover the reporter's desktop, Wayland or
  hardware GPU rendering. Live account/2FA and native Windows acceptance remain
  separate checks.
- macOS bundles use ad-hoc signing without Apple notarization. Updater signatures
  and SHA-256 checksums are supplied separately from operating-system code signing.

## Validation

- Main/release CI passed, and macOS, Windows and Linux release builds passed in
  [run 36373364273](https://github.com/AcrylicShrimp/dlsite-manager/actions/runs/36373364273).
- All 13 uploaded assets were downloaded. SHA-256 checksums, four updater
  signatures with signed version metadata, and all three manifest entries verified.
  The macOS app bundle passed strict, deep code-signature verification.
- The release AppImage ran on OrbStack Ubuntu 22.04 amd64 with IceWM/Thunar.
  Update checking reported “up to date”; a cancelled diagnostic save could be
  retried and exported successfully; the ZIP contained complete records, sanitized
  environment metadata and the successful updater event. Log-folder opening
  displayed the expected directory in Thunar.
- Automatic clipboard copy was unavailable in this Linux session; the support
  summary text fallback appeared. Actual installation of a newer version through
  the updater, native Windows UI, and the reporter's folder-opening environment
  remain unverified.

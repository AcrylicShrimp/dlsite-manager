# ZIP filename encoding

Final decision, 2026-11-15, issue #50.

Honor explicit UTF-8 and validated Unicode Path information. For unlabeled
filenames, decode directly as Windows-31J/CP932 using encoding_rs. Reject
invalid bytes without replacement characters or another encoding fallback.
Do not probe for UTF-8 and do not introduce a statistical encoding detector.
The maintainer chose this policy because DLsite archives predominantly use
Japanese Windows filenames.

Keep decoding in dm-archive, before path validation and directory detection.
On failure, use the existing error path to clean staging and preserve source
archives. No business logic moves to the GUI.

Unlabeled UTF-8 or other encodings may fail or produce incorrect names if their
bytes also happen to be valid CP932. Broader encoding support is deferred until
a concrete case requires it. Explicit Unicode metadata remains authoritative.

The implementation slice is the name decoder, regression tests for ambiguous
UTF-8/CP932 bytes and rejection of unlabeled non-CP932 input, plus the existing
CP932 extraction and decoded-path safety tests. No detector selection remains
open. Real downloaded archive/native-app validation has not been performed.

# Diagnostic logging and support export

## Status and scope

Implemented locally. The original observer design was replaced at the maintainer's
request with unchanged Tauri opener dispatch. Both rounds of verified implementation
findings are corrected; a fresh review of the final consumed-error corrections returned
PASS after the maintainer authorized resuming work. Historical reviews appear below.
Automated/macOS build validation does not establish packaged Linux desktop acceptance.
This supersedes the audit/runtime persistence and collection policy in
[Audit Log System](2026-05-11.00-audit-log-system.md). Job lifecycle and durable
business state remain governed by their existing designs.

The maintainer agreed to one always-on logging system, recording the environment
received by the app and visible immediately before an opener API call. Plugin-owned
child configuration and desktop completion are explicitly unobserved. There is no detailed/debug
recording mode, capture timer, or user-controlled logging level. The limits below
are initial engineering defaults, not additional user settings.

The next release must make failures diagnosable from an exported support bundle,
including AppImage folder opening, without first asking the user to enable logging.
It must not claim to resolve #47 merely because instrumentation was added. Selecting
an app version, implementing, and publishing are separate from this design task.

## Gaps identified before implementation

- `dm-audit` writes audit JSONL; `setup_tracing` separately writes runtime JSON.
  Job logs form a third, bounded in-memory view. There is no common operation context.
- Some command failures become strings through `command_error`; existing library
  `support_details()` is useful but does not cover all command and plugin boundaries.
- `work.open` and `audit.openLogDir` record success when the detached opener returns.
  On Linux the current launcher discards child output and does not observe its exit.
- Startup diagnostics do not describe build identity or the inherited environment.
  Startup failures before the current logger setup cannot use it.
- Sensitive-key filtering covers `details`, not every free-form message or arbitrary
  runtime event. Paths and raw error strings must not be assumed safe for export.
- Daily rotation is not a retention/total-size policy. The Activity log reader loads
  whole files, and opening the log folder depends on the opener being investigated.

## Architecture and ownership

Extend `dm-audit` in place; do not introduce another logging framework or crate just
for renaming. It owns the event contract, safe field representations, context,
serialized writer, bounded reads, retention, logging health, and support archive.
It has no Tauri dependency and does not execute desktop helpers or domain work.

- Tauri owns bootstrap, OS/environment collection, command context, desktop opener
  API instrumentation, native save dialogs, and translation of diagnostics into UI DTOs.
- Domain crates retain business logic and typed errors. They emit selected milestones
  through existing `tracing` instrumentation and return structured failure information.
- `dm-jobs` owns lifecycle, progress, and cancellation. Its task spawn boundary must
  propagate operation context. Its state does not come from log replay.
- The frontend owns presentation, a common invoke/native-plugin error boundary,
  bounded reporting of unhandled UI errors, and export interaction.
- One installed tracing adapter forwards only explicitly approved application events
  into the same safe writer. It is not an unfiltered dump of dependency logs.

Each semantic event is produced once. Activity selects user-facing events from the
same stream; supporting phase events are available in operation details/export.
A command's queue acceptance and its background job's eventual outcome are distinct
events, linked by context. Do not duplicate terminal errors at every catch boundary.
Raw job logs/metadata are not automatically persisted; convert approved fields.
Writer/health internals never emit back through the installed tracing adapter; remove
the current audit-to-tracing echo when switching persistence to avoid recursion.

## Event and context contract

Each persisted event has:

| Field | Contract |
| --- | --- |
| `schemaVersion` | `1` for the new format; independent of app version |
| `runId` | Random ID for one app process, not a persistent installation identity |
| `sequence`, `at` | Intake-ordered sequence within the run and UTC capture time; shared by memory and disk copies |
| `operationId`, `parentOperationId` | Random operation identity and optional parent |
| `jobId` | Existing job identity when applicable |
| `component`, `operation`, `stage` | Stable names, not user-provided strings |
| `kind` | `started`, `milestone`, `finished`, or `diagnostic` |
| `level`, `audience` | Severity and Activity/support visibility |
| `outcome` | For finished operations: `succeeded`, `failed`, `cancelled`, or `unknown` |
| `durationMs` | Monotonic elapsed time, unaffected by wall-clock adjustments |
| `messageCode`, `fields` | Fixed message identity and schema-approved safe fields |
| `error` | Stable code, bounded typed cause chain, and approved machine details |

Generate backend context at handler entry, before domain input validation.
Backend operation IDs are authoritative and included in relevant responses/errors;
frontend-only actions use a bounded client correlation ID until a backend context
exists. Distinguish an IPC transport failure from a backend operation failure.
Tauri can reject argument deserialization or dispatch before a handler runs. Record
these rejections at the frontend invoke boundary using the command name, client
correlation ID, and safe rejection category, without inventing a backend operation ID
or storing the rejected payload. If IPC itself is unavailable, use the frontend ring
and copy fallback. Do not add a custom dispatch framework solely to cover this case.
Propagate context explicitly across spawned tasks and blocking worker boundaries;
thread-local scope alone is insufficient. Events also carry `runId`, so a retained
job identifier from another process cannot be mistaken for the current operation.

Every monitored operation has at most one terminal event. Missing completion after
process termination is shown as incomplete/unknown, never reconstructed as success
or proof of a crash. Parent-child operations keep partial success and cancellation
separate. Retrying creates an attempt under the same parent, with its own outcome.

Preserve typed information before producing a user-facing error string: error kind,
HTTP status, OS error number, approved archive subtype, attempt, duration, and safe
resource references. Do not recursively serialize `Debug`, `Display`, request DTOs,
SQL statements, or an arbitrary error source chain. Extend existing `support_details`
conversions with explicit approved schemas rather than replacing all domain errors.
Existing `bodySnippet` fields must be excluded explicitly, even when their current
URL/serial sanitizer has run. Response-derived information is limited to approved
typed facts/error classifications, never free-form body excerpts.

## Environment snapshots

Collect the process snapshot as early as possible, before database/vault initialization.
This is the environment visible to the app **after** AppImage/AppRun or other launch
wrappers; it is not evidence of the original terminal environment. No reconstruction
of missing original values is attempted.

Persist sanitized run metadata: app version, build revision when available (otherwise
`unknown`), platform/architecture, package kind and detection confidence, executable,
working directory, and OS release fields obtained without dumping system files.
Do not collect hostname, machine ID, hardware serials, or the complete command line.

Environment collection is an allowlist with per-variable representation:

| Variables | Representation |
| --- | --- |
| `APPIMAGE`, `APPDIR` | Sanitized path and presence |
| `PATH`, `LD_LIBRARY_PATH`, `LD_PRELOAD` | Ordered entries, safe path references, and origin classification |
| `GTK_PATH`, `GTK_EXE_PREFIX`, `GTK_DATA_PREFIX`, `GIO_EXTRA_MODULES`, `GIO_MODULE_DIR` | Sanitized paths using the variable's actual list/scalar grammar |
| `XDG_DATA_DIRS`, `XDG_CONFIG_DIRS` | Ordered sanitized paths |
| `XDG_CURRENT_DESKTOP`, `XDG_SESSION_DESKTOP`, `XDG_SESSION_TYPE`, `DESKTOP_SESSION` | Bounded recognized values; unknown values marked unknown |
| `DISPLAY`, `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR` | Presence and safe session/path reference; no remote host/address text |
| `DBUS_SESSION_BUS_ADDRESS` | Presence and recognized transport type; no complete address or GUID |
| `LANG`, `LC_ALL`, `LC_CTYPE` | Validated locale names |
| `RUST_LOG` | Presence only; does not enable broader collection in shipped builds |
| Windows `PATHEXT`, `SystemRoot`, `WINDIR`; macOS `DYLD_LIBRARY_PATH`, `DYLD_INSERT_LIBRARIES` | Applicable-platform validated extensions or sanitized paths |

Distinguish unset, empty, present, invalid/non-Unicode, and truncated values. Retain
path order and empty path-list elements (which can affect executable lookup). Parse
with platform/variable-specific rules rather than splitting every value on `:`.
For diagnostic classification, mark AppDir/host/relative/unknown entries without
modifying the real environment. Symlink resolution failure is recorded, not hidden.
Cap run metadata at 64 KiB, each collected variable at 8 KiB, and each path list at
256 entries. Record omitted counts. Cap in-memory alias tables as well; after their
budget is exhausted, use an explicit unavailable reference rather than retaining
unbounded private strings or writing the original value.

For each opener call, snapshot the relevant current parent environment and record
whether it differs from startup. This is the app's environment at the API boundary,
not evidence of the plugin's child configuration. Do not rebuild commands, resolve
helpers, override variables, or replace dispatch to obtain more diagnostic evidence.
Child environment, selected helper, and desktop completion are explicitly unobserved.

## Data minimization and error output

Apply policy before values reach any disk writer or UI diagnostic buffer. Local and
exported new-format logs have the same policy; export does not unlock raw fields.

- Never record passwords, OTPs, cookies, authorization headers, vault material,
  serial numbers, query strings, signed download URLs, HTTP bodies or body snippets, or arbitrary
  environment variables. Excluding a field is preferable to guessing it is safe.
- Use run-scoped random aliases for account/work identifiers and private paths.
  Keep alias mappings in memory only. No unhashed/plain identifier lookup table is
  included in files or archives, and no stable cross-run identifier is introduced.
- Known application/OS executable names and system directories can remain readable.
  Private path components use aliases; preserve useful facts separately: root kind,
  relative/absolute, spaces/non-ASCII, existence, and required access checks. Preserve
  relationships and environment search order without exposing library filenames.
- Developer-written message templates may accompany approved fields. Free-form
  messages, URLs, third-party logs, frontend error payloads, and child stderr/stdout
  are untrusted input, not automatically safe strings.
- Do not capture desktop helper stdout/stderr or take ownership of its process to
  enrich diagnostics. Record only safe facts returned by the existing opener API.
- Frontend stacks retain source locations/function information only after sanitizing
  paths and URLs. Arbitrary thrown objects, DOM contents, and input values are omitted.

All events are schema-validated and capped at 16 KiB encoded size, with explicit
truncation/omission markers. Reject unknown field types rather than silently passing
arbitrary JSON through. Error cause chains are limited to eight entries.

## Desktop opener boundary

Downloaded-folder opening, log-folder opening, and external URL opening use a small
logging wrapper around the existing Tauri opener plugin on every platform. Preserve
existing download-path canonicalization/root checks, URL validation, and native
integrations. Logging must not change helper selection, fallback, arguments, process
isolation, or inherited environment.

Record sanitized target metadata, the current parent environment, API acceptance or
failure, duration, and safe typed OS errors when the plugin exposes them. API success
means only that the open request was sent; it does not establish a visible window.
Activity says "Open request sent" or "Open request failed".

The plugin owns dispatch. Selected executable, child environment, output, exit status,
and eventual desktop effect remain unknown. There is no custom subprocess runner,
observer task, output pipe, observation deadline, helper reaper, or observer process.
Do not add one merely to collect logs. The maintainer explicitly chose this boundary
following the first implementation review's process-lifetime finding.

## Storage, health, and failure behavior

Use run-specific new-format directories under the existing app log directory:

```text
 diagnostics/<runId>/run.json
 diagnostics/<runId>/events-0001.jsonl
 diagnostics/<runId>/events-0002.jsonl
```

`run.json` contains sanitized startup metadata/environment and collection capabilities.
One writer per process serializes all event appends. Rotate at 4 MiB and at UTC date
boundaries. Initial policy: seven-day retention and a 50 MiB total diagnostics budget.
Oldest closed segments are removed first, then orphaned run metadata. Never delete
another process's active file or an export snapshot in progress. Use explicit file
ownership/locking, not PID age guesses; concurrent app instances must be tested.
If the budget cannot be reclaimed safely, stop disk growth and report degraded health
rather than deleting active data. Retention is bounded housekeeping, not a GUI stall.

Submission uses a bounded queue (1 MiB) and never waits for disk on the UI/domain
thread. Reserve 256 KiB for terminal/error events. On saturation, preferentially drop
routine milestones; count drops by class and expose them in health/export. Critical
events can still be lost under exhaustion; no durability guarantee is invented.
Keep a sanitized 1 MiB in-memory recent-event ring for degraded storage/export.
The serialized intake assigns each event's sequence once, updates the ring, and
submits to the writer queue in that order, without performing disk I/O under the
intake lock. Memory and disk copies retain the same identity even after writer
failure. Eviction/drop counters survive outside the ring, so export can identify gaps.
Flush batches at least once per second during normal operation and use a bounded
shutdown/export flush barrier (two seconds). Each barrier reports its own write/flush
result; historical drops remain in health but do not make later completed barriers
fail. A flush is not a power-loss guarantee.

Logging health is explicit: available/degraded/unavailable, last safe I/O code, dropped
events, truncation, and flush status. Report health directly to the UI
and archive manifest; do not report a writer failure by recursively logging to itself.
Logging failure alone must not cancel downloads or make an otherwise usable app fail.

Bootstrap an in-memory sink before risky app setup, then attach the persistent writer.
If the normal directory cannot be used, retain the bounded ring and show a copyable
startup/support error using the available native/UI path; stderr is an additional
fallback, not the only one on Windows. Capture safe task-panic/join failures where
possible. Never persist arbitrary panic payloads or promise capture of aborts,
segfaults, power loss, or failures before process startup. Avoid logging locks and
allocation-heavy flushing in panic handlers.

Readers stream bounded segments rather than loading whole log history. Export and
retention coordinate through snapshots; malformed/incomplete trailing records are
skipped with explicit counts, not silently treated as complete evidence.

## Coverage for the first release

| Boundary | Required evidence |
| --- | --- |
| All app commands | Validation and terminal failures before string conversion; slow/failing reads, no noisy success audit for polling |
| Native plugin calls | Dialog/open/update/relaunch acceptance or errors and frontend correlation |
| Startup | Build/environment snapshot; directory, DB migration, vault, and initialization stages |
| Auth/sync/network | Endpoint role, attempt/status, duration, timeout/cancel/rejection category; no request secrets/body |
| Download/extract/install/recovery | Phase transitions, byte/file totals, typed I/O failures, retained content and rollback outcomes |
| Jobs/events | Queue/start/finish/cancel, explicit spawn context, receiver lag and emission failures |
| Frontend | Invoke/transport failures, safe unhandled-error summaries, bounded deduplication |
| Desktop opener | Current parent environment, API acceptance/error, explicitly unobserved child configuration and desktop completion |
| Diagnostics itself | Writer/queue/retention/export health without recursive failure |

Normal byte-level progress and polling remain UI state; do not persist every update.
Frontend reporting is bounded (16 KiB per event, at most ten events/second per window),
validated by the backend, and deduplicated with repeat counts. Reporting failure does
not invoke the reporter again. Keep a bounded sanitized frontend ring while IPC is
unavailable, with copy fallback; reconcile IDs and suppress duplicates on recovery.

## Support export and UI

Activity offers a focused operation view and "Export diagnostics". Default export is
the current run; selecting a failed operation includes its parent/child context and
its run metadata. Allow choosing a retained previous run for restart-related failures.
Users do not choose log levels or configure capture sessions.

Archive contents:

```text
 manifest.json       # schema/build IDs, selected scope, limits, omissions, health
 runs/<runId>.json   # sanitized startup/environment snapshots
 events.jsonl        # selected bounded event stream
```

Use a native save dialog and write a ZIP snapshot directly to the selected destination.
This must not depend on opening a folder or launching a browser. Show saved path and
copy-path action. Include a compact copyable support summary even if the save dialog,
archive write, or backend reporting is unavailable. User cancellation is not an error.

For disk input, use only writer-owned, validated files inside the diagnostics store. Do not follow
symlinks, recursively attach the log directory, include arbitrary user-selected files,
or collect the library/database/vault. Also snapshot the sanitized recent-event ring
and in-memory run metadata at the same intake sequence cutoff. Merge disk and memory
events by `(runId, sequence)`, without renumbering or duplicating them. This allows
an unwritable-store run to export recent evidence when its chosen destination is
writable. Record unavailable metadata, evicted ranges, and dropped events; a missing
disk directory does not justify silently exporting an empty event stream.
The snapshot includes the intake sequence cutoff;
record whether the flush barrier completed. For operation-scoped exports, discover
parent/child relationships in a bounded first pass, then filter to that context before
applying the export budget in a second pass. Read at most 50 MiB per pass and retain
at most 65,536 graph nodes; report source/graph truncation explicitly. Stop at 20 MiB
uncompressed and prefer the selected operation, then terminal/error events and nearby
context. State whether the selected operation was found; sequence gaps caused by
scope filtering are explicitly distinguished in the manifest. Mark any omitted
ranges or missing context; never imply a complete run when only a subset was retained.
Creation errors/cancellation remove only the export's temporary file, preserve an
existing destination, and never delete source diagnostics. Archive construction and
filtering stay in `dm-audit`; Tauri handles the save dialog and destination access.
Export snapshots and temporary archives have separate bounded lifetimes and disk
usage (one export per app process, at most 20 MiB source data plus archive overhead);
they do not count as an excuse to grow the 50 MiB retained store without limit.

No automatic upload or remote telemetry service. Display a short description of the
included environment/operation information before saving; do not claim anonymity.

## Existing logs and transition

Stop producing the old parallel audit/runtime files when the new sink is enabled.
Do not dual-write indefinitely. Existing files remain historical read-only evidence;
the new Activity view/export uses new-format records. Do not automatically export old
files: their raw messages/paths did not pass the new collection policy. Clearly show
when no new-format records exist for a requested older operation. Existing legacy
files are excluded from the new 50 MiB budget and are not silently deleted; document
that exception rather than presenting the cap as covering all historical logs.
No database migration and no modification of user content or stored credentials.

## Acceptance scenarios and tests

1. Verify the desktop wrapper delegates to the existing Tauri opener on Linux,
   macOS, and Windows without a custom launcher, pipes, or child environment edits.
   Native/package checks confirm folder/browser requests still reach the desktop;
   API acceptance must never be displayed as proof that a window opened.
2. Contaminated AppDir/PATH/library search: logged parent path order and empty entries
   match the app environment. Include spaces, Unicode, unset/empty variables and
   truncation. Child configuration and helper selection remain explicitly unobserved.
3. Inject auth HTTP/transport failures, disk permission/full errors, archive failure,
   migration failure, cancellation, and recovery. Export identifies the failing stage
   and typed cause while preserving actual job/content outcomes.
4. Concurrent jobs/retries and spawned tasks retain correct run/operation/job linkage;
   no cross-operation mix-up, duplicate terminal events, or reclassification of partial success.
5. Seed secrets/private paths into fields, errors, URLs, panic/UI payloads,
   and unknown environment variables. Inspect actual persisted files and archives,
   not only sanitizer unit outputs. Include an ordinary response body snippet containing
   a secret without URL/serial markers. No raw secret/path mapping or arbitrary error text escapes.
6. Queue saturation, unwritable files, size limits, concurrent instances, retention
   racing export, truncated records, and shutdown mid-write preserve bounded resources
   and truthful health. Business operations remain usable with diagnostic storage disabled.
7. Frontend IPC failure, missing/wrong-type request arguments rejected before handler
   entry, reporter recursion, event floods, backend startup failure, save cancellation,
   and save failure retain a usable summary without requiring an opener. An unwritable
   store with a writable export destination yields deduplicated disk/ring evidence
   and explicit gaps, including when run metadata was never written to disk.
8. Windows/macOS/Linux CI verifies applicable collection/launch/export behavior.
   A packaged Linux AppImage verifies AppRun-visible environment and child dispatch;
   desktop confirmation remains a separate check from API acceptance.

A fresh-reader check of an exported bundle must distinguish failure phase, observed
cause, and unobserved outcome without requiring the original developer's local logs.
An accepted opener request with no visible window remains incomplete evidence and
must not be described as fully diagnosed.

## Tradeoffs and rejected alternatives

- Reject temporary detailed recording, timers, log-level UI, and requiring reproduction
  with a special environment variable. Baseline evidence is always collected.
- Reject full environment/request/response dumps and secret cleanup only at export.
  Approved structured information sacrifices some raw detail for safe routine sharing.
- Reject a remote telemetry stack, a database log store, and a generic process framework.
- Keep `tracing` and the existing audit crate, but remove independent persistence paths.
- Do not rebuild the entire error hierarchy or move business logic into Tauri.
- Do not equate request acceptance, helper exit, and visible desktop effect.

## Implementation notes (2026-09-28)

- `dm-audit` owns intake, sanitization, task-local operation context, the writer,
  retention, health, tracing projection, and ZIP construction. `dm-jobs` explicitly
  carries the command parent into the spawned job and catches task panics without
  persisting their payloads. Commands record typed causes before string conversion.
  HTTP requests emit only endpoint roles/status/duration/transport flags; job phase
  changes and filesystem prepare/install/rollback/cleanup have separate milestones.
- `src-tauri/src/diagnostics.rs` bootstraps diagnostics before directory/database/vault
  setup. Diagnostic commands remain available if ordinary app initialization fails.
  `desktop.rs` wraps the unchanged Tauri opener on every platform and records API
  acceptance/errors only. No custom child dispatch, environment reconstruction,
  stdout/stderr capture, background observer, or reaping remains.
- Open operation tree: app command -> opener API call. Each operation records one
  terminal result. Parent environment is observed immediately before the API call;
  helper selection, child configuration and desktop completion are not observed.
- Environment snapshots retain ordered prefixes and explicit omission counts under
  a combined 6 KiB budget, 8 KiB input per variable, and 256 entries per path list.
  The parent snapshot fits the 16 KiB event bound. Aliases are limited
  to 4,096 entries / 256 KiB of private keys per run, then emit `reference-unavailable`.
  Frontend reports are limited to 64 pending summaries, ten submissions/second and
  repeat counts of 10,000; backend deduplication retains 256 client IDs. No arbitrary
  frontend stack/error text is retained (capability explicitly reports `omitted`).
- Linux records allowlisted distro ID/version and numeric kernel version; macOS records
  the product version. Unsupported platform version collection is explicitly null.
  Build revision is embedded from CI's SHA or the local commit; dirty working changes
  are not represented by that commit hash. Package kind inferred from APPIMAGE is
  labeled as environment-based inference, not authenticated packaging provenance.
- Disk availability is retried, busy store locks have a bounded retry, and a two-second
  exit/export flush is best effort and independent of historical loss counters. The writer can hold one bounded batch in addition
  to the 1 MiB producer queue. Export merges ring/disk identities, prefers terminal/
  error records at its size limit after scope discovery/filtering, and reports malformed records, missing sequence
  ranges (first 256), incomplete operations, and filtering/omission health. Activity's
  recent operation detail is the bounded current-run ring; previous runs are available
  through export. Existing legacy files are neither exported nor automatically deleted.
- `DiagnosticsPanel.svelte` offers current/previous-run export, operation context,
  saved-path copying, and support-summary fallback. No detailed recording mode or
  upload endpoint was added. Existing job UI logs remain transient presentation state.

Validation includes actual JSONL/ZIP secret injection, ring/disk deduplication,
unwritable-store export and recovery, malformed tails, symlink/legacy exclusion,
queue/ring saturation, active-run retention leases, operation concurrency, safe tracing,
frontend IPC failure/deduplication/flooding, typed wrapped I/O/archive causes in actual
JSONL/ZIP files, and an older selected failure in a retained run exceeding 20 MiB.
The earlier custom-observer subprocess tests were removed with that implementation.
Linux packaging/dispatch, Windows runtime, native save-dialog interaction, and live
credentials/network flows remain release acceptance checks; #47 is not proven fixed.


## Independent implementation review (2026-09-28)

One fresh-context read-only reviewer returned **BLOCK**. Parent verification accepted
all three blocking findings and the minor flush finding; no findings were rejected or
left inconclusive. Before/after hashes confirmed no reviewer workspace mutations.

1. **P1 — owned output pipes change launched-process lifetime.** On manager exit,
   its pipe readers disappear. A helper/desktop descendant that writes afterward can
   receive SIGPIPE; `kill_on_drop(false)` and post-deadline draining do not prevent
   this. The observed path also omits the prior detached launcher's `setsid` isolation.
   Both reviewer and parent reproduced closed-pipe exit `-13`, versus `0` with null
   output, using a separate-session subprocess fixture. Existing observer tests keep
   the reader process alive and therefore do not cover this condition.
2. **P2 — scope is applied after the global export budget.** Older selected-operation
   records and graph edges can already be evicted before filtering, despite remaining
   on disk. Discover/filter the selected context before budget-based event selection;
   test a run exceeding 20 MiB with an older failed operation.
3. **P2 — wrapped download/extraction causes lose typed detail.** Download I/O and
   archive errors currently supply only free-form `source`, which is correctly removed
   by privacy projection. Preserve numeric OS errors and approved archive subtypes at
   these conversions, and test the actual persisted/exported differences.
4. **Minor — flush completion depends on historical loss.** A past drop permanently
   makes health degraded, so later completed flush barriers still report false.
   Separate the current barrier result from historical loss counters.

No source fixes were applied in this review turn. The review loop paused under the
fresh-context-review skill's architecture escalation rule. First decide how to retain
independent desktop-process lifetime: move observation/output draining outside the
manager's lifetime, or preserve detached dispatch and reduce output observation.
Do not treat the existing post-deadline draining refinement as resolving app exit.
After that decision, implement the verified corrections and request a new fresh review.

## Independent implementation review, round 2 (2026-09-28)

A new read-only fresh-context reviewer returned **BLOCK**. Parent verification accepted
both findings by source inspection and a compiled projection probe; no findings were
rejected or left inconclusive. All 36 source/document baseline hashes remained unchanged.

- **P2 — bulk item failures lose evidence before the job boundary.** The library
  aggregates failures into `failed_works` after converting typed errors to strings.
  Tauri correctly reports a failed `partial_failure` job, but privacy projection maps
  that code to `unclassified` and drops `failedWorks`. Export retains counts without
  individual aliased work references or typed causes. The corrected single-job cause
  conversion does not cover this consumed-error path.
- **P2 — post-sync local scan failure disappears from successful sync evidence.**
  Tauri constructs structured scan failure information under `output.localScan` and
  intentionally preserves successful sync outcome. Privacy projection drops that
  object, while the warning is only a transient job log. Export therefore loses the
  suboperation failure, including its safe OS code.

The reviewer confirmed original Tauri opener dispatch on every platform, scope-first
export selection, typed wrapped single-job errors, and independent flush results.
Validation passed: workspace Rust tests (live gates disabled), clippy with warnings
as errors, rustfmt check, frontend tests (13), Svelte check (0 errors/warnings), macOS
QA app build and strict/deep signature verification. Native Linux/Windows acceptance
and issue #47 remain unverified.

The review loop is paused under the skill's repeated-blocking-class rule: typed
failure evidence is still lost at another conversion/aggregation boundary. No further
source fix was applied after round 2. The next design correction should explicitly
record bounded, sanitized suboperation failures before bulk aggregation and scan

## Proposed Changes

Add a “Names” Settings tab to `SettingsView.svelte` with a short explanation and one row per language in the editor list. Merge the saved priority first, then all unlisted default and observed codes together in code order, matching the backend's fallback order exactly; the five defaults are only a starting order, never an allowlist. Keep a copy of that merged order as the baseline and derive `priorityDirty` by comparing the current draft with it. Use plain up/down buttons rather than drag-only ordering. Vendor the original English `languages.json`, `territories.json`, and `scripts.json` files unchanged from one pinned, stable Unicode CLDR JSON release, currently 48.2.3, as static frontend data rather than fetching labels at runtime. Retain the original nested map shape; do not hand-curate or copy individual entries. Keep the CLDR version, source links, and required Unicode License v3 notice with the files. For `en_US`-style codes, normalize separators for lookup only, prefer a direct locale name such as `en-US`, then combine the base language with script/region names when present. Always show the original code beside the result; if the code is not covered or cannot be parsed, show the original code alone. A label never changes the stored code, preference ordering, or search behavior. Button labels include the visible name and code for screen readers. The route remains the settings controller. It sends `languagePriority` only when the final draft order differs from its baseline; otherwise the optional field is omitted so the transactional settings patch preserves it. Both Storage and Names tabs use the same save callback and current draft state so switching tabs does not silently lose changes. If code discovery fails, retain the saved/default rows, report the read error, and allow a later retry without clearing the preference.

Do not include the display preference in search requests: backend search already spans all variants. On a successful priority change, invalidate the existing `LibraryQueryController` and detail generation, reset page and reload so old responses cannot overwrite the new projection. Preserve maker selection by the stable key introduced in plan 01. Do not mutate product rows optimistically; use the persisted backend result. A save failure shows the existing error path and retains the draft for correction. Refresh docs and work log when implementation completes.

+ src/lib/data/cldr-48.2.3/{languages,territories,scripts}.json; LICENSE and source note
  copy the three pinned CLDR files unchanged, including every key/value
+ src/lib/utils/language-display-name.ts
+ languageDisplayName(code):
    normalize underscores to hyphens for lookup, retaining original code for display
    direct compound-language lookup; else base language + known script/region names
    absent/invalid lookup -> original code only; never guess a translation

~ src/routes/+page.svelte
+ draftLanguagePriority = defaultPriority
+ savedLanguagePriority = defaultPriority
+ baselineLanguagePriority = defaultPriority
+ priorityDirty = !arrayEquals(draftLanguagePriority, baselineLanguagePriority)
~ loadSettings():
    read getSettings first; retain saved order from its response
    read listNameLanguages; if it fails, report error but keep saved/default codes
    draft = saved order + sorted((default codes union observed codes) minus saved codes)
    baseline = copy(draft)
+ moveLanguage(code, direction): swap adjacent draft entries; recompute priorityDirty
~ revertSettings(): restore roots and draft from saved values; baseline = copy(draft)
~ saveSettings(event):
    submit roots; include draftLanguagePriority only when draft differs from baseline
    on success: update roots and saved priority from returned settings
    if submitted priority changed:
      invalidateLibrary(); reset page; reload list/facets and open detail
    rebuild draft from saved + unlisted codes in code order; baseline = copy(draft)
    on failure: keep draft; show current error notification
~ <SettingsView bind:languagePriority={draftLanguagePriority}
    onMoveLanguage={moveLanguage} ... />

~ src/stories/SettingsView.stories.ts; relevant settings fixtures/tests

+ move then undo, path-only save omits priority and preserves saved subset
+ deferred old list/detail response after successful priority save is ignored

~ docs/designs/2026-08-12.00-frontend-component-workbench.md
+ record the display tab as presentation-only and route-owned persistence/refresh
